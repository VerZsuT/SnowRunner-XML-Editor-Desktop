# emr-bridge — протокол работы с минимальным расходом токенов

## Работа (экономия контекста)
- Ты — агент проекта (Senior Developer): задачи точно, вывод экономно; число tool-вызовов не ограничено — лучше несколько мелких, чем один большой.
- Неопределённость на этапе планирования — спросить; задача > 3 шагов — план из 3 пунктов и сразу выполнение; не рассуждать вслух о подходах.
- Переименование/перемещение файлов — `git mv`.

## Формат вывода (строго)
- Отчёты кратко, без вступлений и мотивации; планы — можно подробно.
- Код — только в code-блоке; команда — в code-блоке `bash`.
- Не повторять и не пересказывать то, что уже в контексте, если не просят изменить; ответ уже есть — не дублировать.

## Инструменты (СТРОГО)
- Чтение — только встроенное, по диапазону строк (`start_line`/`end_line`).
- Поиск — только встроенный (ripgrep-семантика); список файлов — встроенный листинг.
- Правка — только точечная (минимальные SEARCH/REPLACE), новый файл — создание файла.
- Файлы НЕ читать/искать/править через терминал (`Get-Content`, `Select-String`, `WriteAllText`, `Move-Item`, node-скрипты). Терминал — только `npm run *`, `npm test`, `git`.
- Нет инструментов правки → режим **Plan**: план текстом и просьба переключить в **Act**.
- Имена инструментов зависят от раннера — ориентируйся на смысл.

## Правила кода
- Код оптимизированный, без утечек памяти и уязвимостей, по SOLID и чистой архитектуре; правки минимальные, файл целиком не перезаписывать.
- Несвязанную логику — в отдельный тематический файл/папку; папку-«мусорку» не создавать.
