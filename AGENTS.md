# SnowRunner XML Editor — протокол агента

## Проект

Tauri v2: Rust-ядро (`sxmle` → `sxmle-app` → `sxmle-domain` / `sxmle-storage`) и webview
на React 19 + antd 6 + zustand. Electron, `valtio` и `emr-bridge` — архитектура 1.x,
в текущем коде их нет.

Источник правды — `docs/`; при расхождении прав код, документ правится в том же изменении.

## Порядок работы

1. `docs/architecture.md` — слои и границы; `docs/ipc-contract.md` — команды, DTO, события;
   `docs/limits.md` — известные ограничения.
2. Задача — стандартный рецепт? Загрузи скилл до правок:
   - `sxmle-tauri-command` — новая или изменённая команда Tauri, DTO, событие;
   - `sxmle-editor-field` — новое поле редактора;
   - `sxmle-archive` — zip, архив, сохранение;
   - `sxmle-verify` — проверки «как в CI» перед отчётом.
3. Исходники затронутого модуля — после docs; правки минимальные.

## Инварианты

- Rust владеет данными: webview не читает файлы, не разбирает XML и не знает zip.
- Любое действие UI — команда Tauri; обходных путей к ФС нет.
- `src/api/bindings.ts` генерируется (`npm run typegen`), руками не правится.
- У документа `docId` + `revision`; устаревшая мутация отклоняется.
- Правки в памяти; на диск — только явной командой сохранения.
- Запись атомарная (`write_atomic`/zip-слой), не `fs::write`.
- Один формат архива: неизвестная структура — явная ошибка, не догадка.
- Состояние: zustand — только UI; игровые данные — в Rust.

## Команды

Полный список — `docs/commands.md`; CI-прогон — скилл `sxmle-verify`.

- `npm run check`, `npm run lint`, `npm test` — проверки интерфейса;
- `npm run typegen` — пересборка `bindings.ts`;
- `cargo test|check|clippy|fmt` — с `--manifest-path src-tauri/Cargo.toml`.

Cargo-проверки требуют собранного `dist` (`npm run build` или `npx vite build`):
`generate_context!` встраивает фронтенд. Фикстура `initialpak/` локальная — тесты на ней
в CI пропускаются, это не ошибка.

## GUI-проверки

Собранный exe проверяй инструментом `win_gui` (плагин `win-gui`, исходник — `.dsh/plugins/win-gui`):
`list` → `focus`/`place` → `shot` → `click`/`type`/`keys`; нативные диалоги — `ui`/`ui_click`.
Координаты клика — от клиентской области окна: `x`/`y` в пикселях снимка (после `shot`) или
`fx`/`fy` долями 0..1 (без снимка). Экранные координаты не вычисляй — их считает инструмент.
Снимок смотри через `read_image`, затем правь по нему. Нет инструмента — плагин не установлен.

## Правки

- Файл целиком не перезаписывать; несвязанную логику — в отдельный тематический файл,
  папку-«мусорку» не создавать.
- Rust: `thiserror`, без `unwrap`/`expect` в пользовательских путях; комментарии и тесты на русском.
- TS: табы, LF, одинарные кавычки, без `;`, strict, `import type`, SCSS рядом с компонентом.
- Переименование/перемещение — `git mv`.
- Обнови затронутый документ `docs/` и, если нужно, `limits.md`/`changelog.md`.

## Инструменты

- Чтение, поиск и правка — встроенными инструментами (по диапазонам строк), не через терминал.
- Терминал — только `npm`, `npx`, `node scripts/*`, `cargo`, `rustc`, `git`, `gh`, `tauri`.
- Долгие прогоны (сборка, тесты) — фоном, не держи turn открытым.

## Формат вывода

- Отчёты кратко, без вступлений и мотивации; план — до 3 пунктов и сразу выполнение.
- Код — только в code-блоке; команда — в code-блоке `powershell`.
- Не дублировать сказанное; ответ уже есть — не пересказывать.
