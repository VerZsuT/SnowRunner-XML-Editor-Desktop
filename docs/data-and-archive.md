# Данные, архив и обновления

## Каталоги данных

Каталог выбирается при старте ([paths.rs](../src-tauri/crates/app/src/paths.rs)):

| Режим | Условие | Каталог данных |
|---|---|---|
| `installed` | обычный запуск | `%APPDATA%\SnowRunner XML Editor` |
| `portable` | рядом с `.exe` есть `portable.txt` | `<каталог exe>\data` |
| `dev` | `tauri dev` | `%APPDATA%\SnowRunner XML Editor` |

Маркер `portable.txt` создаётся переключателем в настройке; в режиме разработки
переключение запрещено. Смена режима копирует только `jsons/*.json` и не переносит
`mainTemp`, `modsTemp` и бэкапы.

```text
<data_root>/
  jsons/
    config.json          конфигурация
    favorites.json       избранные файлы
    edited.json          изменённые файлы
    mods.json            установленные моды
  mainTemp/              распакованные файлы основной игры/DLC
    [media]/classes/...
    [media]/_templates/...
    [media]/_dlc/...
    [strings]/...
  modsTemp/<мод>/        распакованные файлы мода
  backups/
    initial.pak          основной бэкап
    initial_<suffix>.pak датированный бэкап (если передан suffix)
    previous_initial/    зарезервировано, автоматически не создаётся
  updateTemp/            загруженный установщик или zip
```

`PathsDto` также отдаёт `sizes.json`, `game-texts.json`, `exported.json`, но текущий код
их не создаёт и не использует. Не считайте их источником состояния.

## `initial.pak`: распаковка

1. Пользователь выбирает `initial.pak`; путь сохраняется в `config.json`.
2. `unpack_initial` открывает архив и извлекает записи по встроенному списку:
   `main`, `optimized` (используется интерфейсом) или `mods`.
3. Файлы пишутся в `mainTemp`; структура каталогов совпадает с записями архива.
4. На экране настройки перед распаковкой вызывается бэкап; в пустом состоянии списка
   распаковка идёт **без бэкапа**.

Списки лежат в [crates/app/lists](../src-tauri/crates/app/lists) и встроены в бинарник
через `include_str!`. Это данные, а не WinRAR-специфика.

Распаковка **не очищает** `mainTemp`. Если архив игры обновился, старые файлы могут остаться
и позже попасть в пересобранный архив. Перед повторной распаковкой удаляйте `mainTemp`
вручную или используйте чистый каталог данных.

## `initial.pak`: обновление

`update_archive`:

1. Проверяет, что архив и каталог существуют; каталог не пуст.
2. Собирает файлы каталога рекурсивно; имя записи — относительный путь с `\`.
3. Сравнивает каждый файл с записью архива по CRC32 и размеру.
4. Изменённые записи пересобирает, неизменённые копирует сжатым потоком.
5. Новые записи добавляет в конец, затем добавляет пустой маркер `edited`.
6. Атомарно заменяет архив.

Следствия:

* архив пересобирается целиком, даже если изменений нет; маркер `edited` добавляется всегда;
* порядок существующих записей и их метаданные сохраняются;
* метод сжатия изменённой записи сохраняется (stored или deflate);
* zip64, data descriptor и шифрование не поддерживаются — ошибка до записи;
* бэкап автоматически не создаётся. Кнопка «Бэкап» в настройке — отдельное действие.

Для мода каталог — `modsTemp/<мод>`, имя мода проверяется на пустоту, `..`, `/`, `\`, `:`.

## Сохранение документа

`save_document`:

1. Берёт XML-дерево из памяти Rust.
2. Форматирует: 2 пробела, CRLF, самозакрывающиеся пустые теги.
3. Кодирует в исходной кодировке с исходным BOM и объявлением.
4. Пишет атомарно в исходный файл (в `mainTemp` или `modsTemp`).

Сохранение не трогает `initial.pak` и не создаёт бэкап. Чтобы изменения попали в игру,
нужно отдельно нажать «Обновить архив» (для основной игры) или обновить мод.

Форматирование нормализует файл: побайтовый diff может быть большим, даже если изменено
одно значение. Это ожидаемо.

## Бэкапы и восстановление

| Действие | Поведение |
|---|---|
| `backup_archive(path, null)` | копия в `backups/initial.pak`, перезапись |
| `backup_archive(path, suffix)` | копия в `backups/initial_<suffix>.pak` |
| `restore_backup(path)` | копирует **только** `backups/initial.pak` поверх архива |
| `verify_archive(path)` | распаковывает все записи, проверяет CRC и размер |

Датированные бэкапы не восстанавливаются из UI: их нужно скопировать в `initial.pak` вручную.
Перед восстановлением закройте игру.

## Моды

`add_mod`:

1. Проверяет, что `.pak` существует.
2. Формирует имя: `sanitize_name` (пробелы → дефис, запрещённые символы удаляются,
   точки схлопываются, обрезка до 80 символов, зарезервированные имена Windows получают `_`).
3. Распаковывает в `modsTemp/<имя>` по списку `mods`.
4. Требует каталог `classes`; иначе удаляет распакованное и возвращает ошибку.
5. Сохраняет запись в `mods.json`.

`remove_mod` убирает запись из `mods.json`, но **не удаляет** `.pak` и `modsTemp/<имя>`.
`sync_mods` удаляет записи с пропавшими `.pak` и пересобирает распаковку, если размер
файла изменился. Сравнение только по размеру: мод, изменённый с тем же размером,
не пересоберётся.

Файлы мода открываются как обычные документы; сохранение идёт в `modsTemp/<имя>`,
а `update_archive(path, modName)` пишет их в `.pak` мода.

## Игровые переводы

`game_texts(lang)` читает:

* `mainTemp/[strings]/strings_<язык>.str` — основная игра;
* `modsTemp/<мод>/texts/strings_<язык>.str` — моды.

Формат — UTF-16LE, по строке `ключ "значение"`. Приоритет: строки мода, затем игры.
Если файла нет, остаются ключи и имена файлов.

## `.epf`: обмен параметрами

Формат версии 3.0 — JSON:

```json
{
  "version": "3.0",
  "info": [{ "name": "ank_mk38", "isTrailer": false, "dlc": null, "mod": null }],
  "data": { "<имя>_<источник>": { "/Truck/TruckData": { "FuelCapacity": "200" } } },
  "actionsData": { "<имя>_<источник>": { "cranes": {}, "trailers": {} } }
}
```

* экспорт идёт из дерева в памяти, сохранять документ перед экспортом не нужно;
* экспорт дополняет совместимый файл и заменяет файл другой версии;
* импорт проверяет версию и запись `info`, применяет известные атрибуты, неизвестные пути
  пропускает, добавляет недостающие краны/прицепы;
* работают только с документами трака или прицепа;
* импорт меняет `revision` один раз, если применил хотя бы одно изменение.

## Обновление программы

`check_update`:

1. Если `checkUpdates = false` и `force = false` — выходит.
2. Читает `<pages>/version-info.json` (HTTPS, таймаут 10 с, ответ ≤ 64 КиБ).
3. Сравнивает версии по числам и суффиксу; возвращает новую версию или `null`.

`download_update`:

* проверяет версию по формату и собирает URL
  `<releases>/v<версия>/SnowRunnerXMLEditor.exe` или `SnowRunnerXMLEditor.zip`;
* качает в `updateTemp`, сообщает прогресс событием `update-progress`;
* таймаут соединения 30 с, общий — 10 минут.

`run_installer`:

* требует, чтобы файл лежал внутри `updateTemp` (канонизация путей);
* установщик запускается, портативный zip открывается в проводнике;
* приложение закрывается.

Подписи и хеш загруженного файла не проверяются: доверие строится на HTTPS и GitHub Releases.

## Что делать при сбое

| Симптом | Проверить |
|---|---|
| «Игра не видит изменений» | сохранён ли документ и нажато ли «Обновить архив» |
| Архив не читается | `verify_archive`, затем восстановить `backups/initial.pak` |
| После обновления игры странные данные | удалить `mainTemp` и распаковать заново |
| Мод не обновился | сравнить размеры `.pak`; удалить `modsTemp/<мод>` и добавить заново |
| Обновление не предлагается | `site/version-info.json`, наличие файлов в GitHub Releases, HTTPS |

См. также [limits.md](limits.md) — там перечислены ограничения, которые влияют на эти сценарии.
