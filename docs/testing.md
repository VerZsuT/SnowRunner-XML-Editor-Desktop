# Тесты

## Уровни

| Уровень | Где | Что проверяет |
|---|---|---|
| Rust unit | `#[cfg(test)] mod tests` рядом с модулем | значения, дескрипторы, лимиты, шаблоны, селекторы, zip-заголовки, EPF, пути |
| Rust integration | `crates/*/tests` | XML на фикстурах, документы, архивы, игра |
| Vitest node | `src/tests/api`, `localization`, `strings` | чистые преобразования, словари, строки |
| Vitest jsdom | `src/tests/components`, `tests/pages` | компоненты и экраны с Testing Library |
| Ручной чек-лист | ниже | то, что нельзя проверить в CI: реальная игра и Windows |

E2E, визуальных и нагрузочных тестов нет.

## Запуск

```powershell
npm test                 # все Vitest-проекты
npm run test:watch       # watch
npm run test:coverage    # coverage
npx vitest run --project node
npx vitest run --project jsdom

cargo test --manifest-path src-tauri/Cargo.toml --workspace --all-targets
cargo test --manifest-path src-tauri/Cargo.toml -p sxmle-storage
cargo test --manifest-path src-tauri/Cargo.toml -p sxmle-domain
cargo test --manifest-path src-tauri/Cargo.toml -p sxmle-app
```

Перед `cargo test` нужен `dist`: `npm run build` (иначе `generate_context!` не соберётся).

## Rust-тесты

* Имена тестов — русские, описывают сценарий.
* Модульные тесты лежат в `tests.rs` рядом с модулем.
* Интеграционные тесты — в `crates/<crate>/tests/`.
* `cargo clippy --workspace --all-targets -- -D warnings` и `cargo fmt --check` обязательны.

### Фикстура `initialpak/`

Каталог `initialpak/` не хранится в git (см. `.gitignore`). В нём лежат:

* `initial.pak` — копия архива игры;
* `[media]/classes` — распакованные XML;
* `[media]/_templates`, `[media]/_dlc`, `[strings]`.

Интеграционные тесты `game`, `documents`, `game_fixture` проверяют наличие каталога
и **пропускаются**, если его нет. В CI фикстуры нет, поэтому эти тесты не выполняются;
локально они дают основную проверку реальных файлов.

Тесты, которым нужна запись, копируют фикстуру во временный каталог
(`CARGO_TARGET_TMPDIR`) и не портят оригинал.

### Что покрыто

* lossless-разбор и форматирование XML, кодировки, сущности, несколько корней;
* селекторы и мутации;
* шаблоны `_templates`;
* модели Truck/Engine/Gearbox/Suspension/Winch/Wheels/Addon на фикстуре;
* реестр документов: открытие, версии, сохранение, сброс, EPF, действия;
* выгрузка значений по умолчанию: преобразование селекторов и наличие файла `winches_medium_trucks`;
* zip: чтение, обновление, порядок, CRC, атомарность, отказ от шифрования и от записей
  больше 512 МиБ, разбор central directory без локальных заголовков (`read_entries`);
* отпечаток архива: канонический CRC, сравнение, хранилище, чтение старого маркера
  `edited` как диагностики, состояния `ok`/`changed`/`unknown`, регистронезависимость
  путей на Windows;
* журнал полей: сбор `base`/`value` при сохранении, дедупликация, снятие метки и сброс;
* восстановление после обновления игры: кандидаты, 3-way, решения, режим «нет истории»,
  обновление журнала после применения;
* чистая распаковка: старый `mainTemp` не смешивается с новым, копия в `previous_initial`,
  сбой не портит рабочий каталог, внешняя замена блокирует `update_checked`,
  `restore_backup` даёт `changed` или `ok`;
* моды: имена каталогов и staging-распаковка (битый `.pak` сохраняет прежний мод);
* пути и режимы данных;
* команды: суффикс датированного бэкапа;
* обновления: версии, URL, имена файлов.

### Восстановление после обновления игры

* `domain/src/game/editable/tests.rs` — сбор полей всех видов, служебные атрибуты и
  `_templates` не попадают, `Exact` не задевает вложенные `Body`, `apply` удаляет при
  `None`, `label` находит подпись.
* `crates/app/src/changes/tests.rs` — сохранение: первая правка, повторная, возврат
  к базе, сдвиг базы после смены версии игры, очистка, пустые `fields`; восстановление:
  «моё»/«игры»/совпадение/пропавший элемент/«нет истории».
* `crates/app/src/recovery/tests.rs` — кандидаты из `edited.json` и журнала, `history`,
  одинаковые файлы пропускаются, моды, дедупликация, 3-way, «нет истории», действия.
* `crates/app/src/lists/tests.rs` — журнал: добавление, замена по `archiveName`, пустые
  `fields`, битый файл, снятие метки удаляет запись.
* `src-tauri/src/commands/documents.rs` (unit) — снимок и слияние: сохранение двигателя,
  трака, аддона; нечитаемый старый файл не меняет журнал; вид без правил не пишется.
* `crates/app/tests/recovery.rs` — интеграционные сценарии: 3-way, решение «игры»,
  поле вне журнала, совпавшее поле не пишет документ, трак без истории (restore/skip),
  связанный документ без журнала, аддон с `TruckData`, битый XML, изменившийся архив,
  отмена, повторный запуск, DLC, устаревший план, пропавший новый файл.
* `crates/app/tests/archive.rs` — `update_from_dir` не добавляет `edited`; старый маркер
  сохраняется и остаётся диагностикой; списки распаковки без `edited`; новые архивы
  маркер не получают.

## Vitest

Два проекта в [vitest.config.ts](../vitest.config.ts):

| Проект | Environment | Include |
|---|---|---|
| `node` | node | `tests/api/**/*.test.ts`, `localization.test.ts`, `strings.test.ts` |
| `jsdom` | jsdom | остальные `*.test.{ts,tsx}` |

Особенности:

* `tests/setup.ts` добавляет `matchMedia`, `ResizeObserver`, `IntersectionObserver`, `scrollTo`;
* `@ant-design/icons` заменяется на ESM-вход: CJS-вход ломает именованные экспорты;
* `deps.optimizer` предсобирает antd/react — иначе тысячи модулей;
* пул `threads`, `maxWorkers: 100%`.

Экраны принимают клиентов и загрузчики пропсами (`client`, `load`, `lists`, `texts`).
В тестах подменяйте их, а не `vi.mock` всего модуля. Исключение — сетевой слой
`src/tests/api/watch.test.ts`: он подменяет `@/api/bindings`, чтобы проверить включение
и выключение backend-watcher без Tauri.

Покрытые сценарии UI: сохранение всех документов снимает звёздочку правок, быстрые
переключения настроек не теряют первую правку, устаревший ответ списка не перезаписывает
кэш после сброса, watcher выключается после последней отписки, окно целостности архива
блокирует запись и умеет перечитывать архив. Окна восстановления после обновления игры
покрыты `src/tests/components/recovery.test.tsx`.

## CI

`.github/workflows/ci.yml`:

| Job | Шаги |
|---|---|
| `verify` | Node 24, `npm ci`, `check`, `lint`, `test` |
| `rust` | `npm ci`, `npx vite build`, `typegen` + `git diff --exit-code bindings.ts`, `cargo test`, `clippy`, `fmt --check` |
| `package` | по тегу или `workflow_dispatch`: `npm run tauri:build`, установщик и портативный zip в артефакты |

`package` не публикует релиз автоматически: файлы нужно приложить к GitHub Release.

## Ручной чек-лист

Минимум перед релизом:

1. Чистая Windows 11: установка NSIS, запуск, окно 800×600 логических (~1000×800 с заголовком при 125%), список траков.
2. Первый запуск без `config.json`: язык по локали системы, экран первоначальной
   настройки, выбор папки игры и `initial.pak`, распаковка; смена языка на шаге 1 сразу
   переводит меню и шаги.
3. Windows 10 без WebView2 (или с удалённым): установщик ставит компонент при наличии сети.
4. Портативный zip: `portable.txt` рядом с exe, данные в `data`.
5. Выбор `initial.pak`, распаковка, список траков и прицепов: карточки с картинками,
   переключение на строки, сворачивание фильтров, подсветка поиска, избранное,
   меню правого клика (избранное, экспорт, импорт, сброс).
6. Открытие трака, правка нескольких полей, сохранение (архив обновляется сразу);
   «Сбросить» возвращает значения из выгрузки 1.4.0 и оставляет звёздочку несохранённых правок.
7. Запуск игры с пересобранным архивом: трак загружается, параметры применились.
8. Бэкап, изменение, восстановление бэкапа.
9. DLC-трак и мод: открытие, правка, сохранение с автоматическим обновлением архива/мода.
10. Игровые переводы названий; переключение языка в настройках: меню, списки, окно настроек
   и окно «Что нового» меняются сразу, остальной интерфейс — после перезагрузки окна.
11. Экспорт/импорт `.epf` (импорт сразу обновляет архив), краны, прицепы, «Банан бандита» (Zikz 605R).
12. Переключение портативного режима, перезапуск, сохранность json.
13. «Настройки → Сбросить»: программа возвращается к первоначальной настройке,
   распакованные данные, бэкап и списки удалены; «Настройки → Удалить программу»
   запускает `uninstall.exe` (только для установленной сборки).
14. Проверка обновления: `version-info.json`, загрузка, установка, портативный zip.
15. Закрытие с несохранёнными правками: предупреждение; закрытие приложения — правки теряются.
16. Внешняя правка файла открытого документа: модель перечитывается, несохранённые правки
    этого документа отбрасываются.
17. Заменить `initial.pak` при закрытой программе: при старте окно «Архив изменился»,
    сохранение заблокировано; «Перечитать архив» оставляет старые файлы в
    `backups/previous_initial`, а в `mainTemp` — только файлы нового архива.
18. Заменить архив при открытом редакторе: сохранение отказывает, архив не изменён;
    после перечитывания документы закрыты. Повторная распаковка того же архива окна не даёт.
19. Восстановить бэкап: окно со статусом `changed` (или без окна, если копия совпадает).
20. Сохранение модового документа при изменившемся основном архиве работает.
21. Восстановление параметров после обновления игры — сценарий [USER-ACTIONS §3.3](../plans/USER-ACTIONS.md):
    трак, двигатель, аддон, замена архива, конфликт, «Моё»/«Игры», отмена, удалённый файл,
    мод, трак без истории; после сохранения маркер `edited` не появляется.

## Что тестировать при изменении

| Изменение | Обязательные тесты |
|---|---|
| XML/селектор | `cargo test -p sxmle-domain`, фикстуры `xml_core`, `xml_fixture` |
| Модель/поле | unit-тест сущности + `game_fixture` при наличии фикстуры |
| Поле в журнале/восстановлении | правило в `crates/domain/src/game/editable.rs` + `editable/tests.rs`; `crates/app/tests/recovery.rs` |
| Команда | Rust-тест сценария + проверка `bindings.ts` через `typegen` |
| Документы/сохранение | `crates/app/tests/documents.rs` (копия фикстуры) |
| Zip | `cargo test -p sxmle-storage` |
| Отпечаток/распаковка архива | `integrity::tests`, `crates/app/tests/archive.rs`, `crates/storage/src/zip/tests.rs` |
| Экран/компонент | Vitest jsdom с подменённым клиентом |
| Локализация | `localization.test.ts`; структура `Locale` проверяется `tsc` |
| Конфигурация | `config/tests.rs`, `components/settings.test.tsx` |
| Первоначальная настройка | `pages/welcome.test.tsx`, поиск архива в `crates/app/tests/archive.rs` |

## Пробелы

* Нет E2E с настоящим окном Tauri.
* Нет проверки запуска игры в CI.
* Нет тестов watcher (`notify`) и задержки `documents-changed`.
* Нет тестов на повреждённый архив/сбой питания, кроме unit-сценариев.
* Нет порога покрытия.
* Фикстурные тесты в CI пропускаются.
