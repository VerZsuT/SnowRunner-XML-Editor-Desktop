# Интерфейс (React)

## Стек

* React 19, `react-dom`, StrictMode;
* antd 6 + `@ant-design/icons`;
* zustand 5 — только UI-состояние;
* SCSS рядом с компонентами;
* Vite 8 + TypeScript 7, React Compiler включён в плагине Vite;
* тесты — Vitest + Testing Library (jsdom), чистая логика — в node-проекте.

## Точка входа

`src/index.html` → `entry.tsx`:

1. читает конфигурацию через `loadConfig()` (ошибка не блокирует запуск);
2. `registerConfig(fromConfigDto(dto))` применяет язык через `setTexts`;
3. **динамически** импортирует `app.tsx` — тексты и локаль antd фиксируются при импорте,
   поэтому язык должен быть известен до загрузки модулей;
4. монтирует `ConfigProvider` с локалью antd и `AntApp`.

Смена языка в настройке сохраняет конфигурацию и перезагружает окно.
Отдельного рантайм-переключения строк нет.

## Навигация

`app.tsx` — плоская навигация без роутера:

* `ListsPage` — стартовый экран;
* `EditorPage` — открытый трак/прицеп;
* `SetupPage` — настройка;
* поверх — `UpdateAlert` и `WhatsNew`.

Состояние навигации — локальные `useState`; выбранный документ передаётся пропсами.
zustand хранит только снимок конфигурации, игровые данные в нём не живут.

### Контракт команд

Команды, возвращающие `Result`, приходят как `CommandResult<T>`:

```ts
type CommandResult<T> =
  | { status: 'ok', data: T }
  | { status: 'error', error: CommandError }
```

`call()` разворачивает результат в `T` или бросает `CommandFailure` с `code` и `path`.
Безошибочные команды (например, `list_documents`) возвращают значение напрямую.
Подробнее — [ipc-contract.md](ipc-contract.md).

### DocumentSession

`DocumentSession` — обёртка открытого документа:

* хранит `DocumentInfo` (`docId`, `revision`, `dirty`);
* все мутации проходят через очередь `enqueue`, поэтому версия всегда актуальна;
* `subscribe` уведомляет компоненты об изменении `dirty`/`revision`;
* `save`, `reset`, `exportEpf`, `importEpf`, `close` тоже сериализуются;
* ошибка операции не ломает очередь.

### Поля

`fieldValue(field)` возвращает `value ?? defaultValue`.
`writeField` форматирует значение и вызывает `setAttr`; `resetField` пишет `defaultValue`.
Формат совпадает с Rust: числа, `true`/`false`, список через запятую, позиция `(x; y; z)`.

## Экраны

### Списки (`pages/lists`)

* категории «траки» / «прицепы»;
* фильтры: источник (все, основная игра, DLC, моды, избранное, изменённые), класс, поиск;
* избранное и метка изменённого файла;
* названия берутся из игровых переводов, иначе — ключ или имя файла;
* пустое состояние предлагает выбрать `initial.pak` и распаковать;
* переход в редактор передаёт `name`, `kind`, `modName`.

Распаковка из пустого состояния **не делает бэкап** — в отличие от кнопки на экране настройки.

### Редактор (`pages/editor`)

`TruckTable` собирает группы параметров:

* тексты, управляемость, лебёдка, колёса, подвески, коробки, двигатели, топливо;
* физическая модель (вложенные тела);
* разблокировка и цена;
* содержимое аддонов;
* сокеты аддонов (секции, сокеты, сдвиги) с добавлением/удалением/перестановкой;
* краны, прицепы, «Банан бандита».

Связанные документы открываются по сокетам трака: двигатели, коробки, подвески, лебёдки,
наборы колёс из `CompatibleWheels`. Отсутствующий файл пропускается.
Аддоны открываются по кнопке; повторное открытие возвращает существующий документ.

Шапка редактора: назад, сброс, сохранить всё, экспорт/импорт `.epf`, перечитать.
При несохранённых правках назад и сброс требуют подтверждения.
Сохранение вызывает `save_all_documents`, а не пересборку архива.

### Настройка (`pages/setup`)

* пути и режим данных;
* выбор `initial.pak`, распаковка (с бэкапом), обновление архива, бэкап, проверка, восстановление;
* установленные моды: добавить `.pak`, обновить, удалить из списка, синхронизировать;
* опции: моды, расширенный режим, портативный режим, проверка обновлений, язык.

Переключение режима данных требует перезапуска; смена языка — перезагрузки окна.
Клиент экрана (`setup/client.ts`) подменяется в тестах целиком.

## Компоненты полей

`DocumentField` выбирает контрол по `descriptor.attrType`:

| Тип | Контрол |
|---|---|
| `integer`, `float` | `InputNumber`; `fixed` и integer округляются |
| `boolean` | `Select` да/нет |
| `position` | три `InputNumber` |
| `stringArray` + `options` | `Select` с множественным выбором |
| остальные | `Input` или `Select` при наличии `options` |

Пустой список строк с непустыми `options` трактуется как «все значения» — так же,
как в прежнем интерфейсе. Сброс поля — через контекстное меню; подсказка — из `desc`.

## Локализация

`src/utilities/localization`:

* `Lang` — `RU`, `EN`, `DE`, `CH`;
* `ru.ts` — эталон структуры, тип `Locale` выводится из него;
* `en.ts`, `de.ts`, `ch.ts` обязаны совпадать по структуре (проверяет TypeScript);
* `T` — выбранный словарь, `setTexts(lang)` вызывается один раз при старте.

Тексты экранов лежат в `T.lists`, `T.editor`, `T.setup`, `T.updateAlert`, `T.whatsNew` и `T.dictionaries`.
Подписи полей редактора — `FIELD_TEXTS` в `pages/editor/texts.ts`:
ключ из Rust `модуль.поле` → строка словаря. Значения enum — `OPTION_TEXTS`.

Часть подписей задана русскими строками прямо в `FIELD_TEXTS`; при переводе на другие языки
они останутся русскими. Это известное ограничение (см. [limits.md](limits.md)).

## Состояние и правила

* zustand — только UI-конфигурация; новые межпроцессные данные через него не заводить.
* Игровые данные и документы — в Rust; в компонентах держите только загруженные DTO.
* Локальные черновики полей допустимы, но запись идёт через `DocumentSession`.
* Не обходите `DocumentSession` прямыми вызовами `commands.*` в компонентах.
* Клиенты и загрузчики передавайте пропсами с дефолтом — это точка мока в тестах.

## Стили

SCSS-файл рядом с компонентом (`field.scss`, `lists.scss`, ...); каждый экран/компонент
импортирует свой стиль. Отдельного глобального SCSS-файла нет. Используются CSS-переменные antd.
