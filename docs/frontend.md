# Интерфейс (React)

## Стек

* React 19, `react-dom`, StrictMode;
* antd 6 + `@ant-design/icons`;
* zustand 5 — только UI-состояние;
* SCSS рядом с компонентами;
* Vite 8 + TypeScript 7, React Compiler включён в плагине Vite;
* тесты — Vitest + Testing Library (jsdom), чистая логика — в node-проекте.

## Точка входа

`src/index.html` → `entry.tsx`:

1. читает конфигурацию через `loadConfig()` (ошибка не блокирует запуск);
2. `registerConfig(fromConfigDto(dto))` применяет язык через `setTexts`;
3. **динамически** импортирует `app.tsx` — тексты и локаль antd фиксируются при импорте,
   поэтому язык должен быть известен до загрузки модулей;
4. монтирует `ConfigProvider` с локалью antd и `AntApp`.

Смена языка в настройках сохраняет конфигурацию и перезагружает окно.
Исключение — верхнее меню, списки, окно настроек, экран игровых данных, окно «Что нового»
и шаг с языком в первоначальной настройке: они читают тексты из `LOCALES` по текущему языку
конфигурации и меняются сразу, не дожидаясь перезагрузки.

Если `config.json` ещё нет, язык по умолчанию определяет Rust по локали системы
(`sys-locale`): `ru`→RU, `en`→EN, `de`→DE, `zh`→CH, иначе EN. Первоначальная настройка
берёт тексты из `LOCALES` по выбранному языку, поэтому шаг с языком обновляется без
перезагрузки; окно перезагружается после распаковки архива.

## Навигация

`app.tsx` — плоская навигация без роутера:

* `WelcomePage` — первоначальная настройка: язык программы и игровые данные;
* `ListsPage` — стартовый экран;
* `EditorPage` — открытый трак/прицеп;
* поверх всех экранов — `MenuBar` (Файл, Бэкап, Настройки, Помощь), `UpdateAlert` и `WhatsNew`.

`MenuBar` повторяет меню 1.4.0: «Файл» — открыть распакованные файлы, обновить или
распаковать архив и выход; «Бэкап» — открыть каталог, сохранить и восстановить;
«Настройки» — окно настроек, сброс к первоначальному состоянию и удаление программы;
«Помощь» — версия, руководство, GitHub, YouTube, поддержка.
Пункты, которым нужен `initial.pak`, блокируются, пока архив не выбран.

Состояние навигации — локальные `useState`; выбранный документ передаётся пропсами.
zustand хранит только снимок конфигурации, игровые данные в нём не живут.
Список при открытии редактора не размонтируется, а скрывается:
фильтры, вид списка и позиция скролла сохраняются без отдельного хранилища.

## Окно

Окно `general` — 800×600 логических пикселей; это же значение задаёт минимальный размер
(`tauri.conf.json`). При масштабе 125% содержимое занимает 1000×750, а окно вместе
с заголовком — около 1000×800.

### Контракт команд

Команды, возвращающие `Result`, приходят как `CommandResult<T>`:

```ts
type CommandResult<T> =
  | { status: 'ok', data: T }
  | { status: 'error', error: CommandError }
```

`call()` разворачивает результат в `T` или бросает `CommandFailure` с `code` и `path`.
Безошибочные команды (например, `list_documents`) возвращают значение напрямую.
Подробнее — [ipc-contract.md](ipc-contract.md).

### DocumentSession

`DocumentSession` — обёртка открытого документа:

* хранит `DocumentInfo` (`docId`, `revision`, `dirty`);
* все мутации проходят через очередь `enqueue`, поэтому версия всегда актуальна;
* `subscribe` уведомляет компоненты об изменении `dirty`/`revision`;
* `save`, `reset`, `resetDefaults`, `exportEpf`, `importEpf`, `close` тоже сериализуются;
* ошибка операции не ломает очередь.

### Поля

`fieldValue(field)` возвращает `value ?? defaultValue`.
`writeField` форматирует значение и вызывает `setAttr`; `resetField` пишет статический `defaultValue`, а поля редактора берут значение из выгрузки 1.4.0 через `useFieldDefault`.
Формат совпадает с Rust: числа, `true`/`false`, список через запятую, позиция `(x; y; z)`.

## Экраны

### Списки (`pages/lists`)

* категории «траки» / «прицепы»;
* два вида: карточки с обложкой (по умолчанию) и строки с миниатюрой; кнопка в шапке переключает вид;
* кнопка-воронка сворачивает и разворачивает панель фильтров с анимацией высоты;
* фильтры: категория, источник (все, основная игра, DLC, моды, избранное, изменённые), класс, поиск;
* панель фильтров и кнопки шапки повторяют размеры 1.4.0; hover кнопок меняет только цвет
  иконки — рамка Ant Design погашена, белая окантовка не мигает;
* фон списка — `#e7ebf0`, как в 1.4.0; `scrollbar-gutter: stable` не даёт карточкам
  менять ширину при появлении и исчезновении полосы прокрутки (например, в «Избранном»);
* полоса прокрутки берётся из глобальных стилей, как в 1.4.0: 4px, ползунок `#808080`
  (`#c7cfc1` на hover), трек `#535151`;
* совпадение поиска подсвечивается в названии;
* избранное и метка изменённого файла — значки, как в 1.4.0;
* названия берутся из игровых переводов, иначе — имя файла в верхнем регистре;
* на время первой загрузки показывается skeleton-card/skeleton-row, повторяющий сетку;
* в режиме строк hover меняет яркость слоя, а не фон: `box-shadow` не мигает;
  миниатюры слегка размыты (`blur(0.4px)`), потому что сжатые превью слишком резкие;
* в источнике «Моды» показывается кнопка «Изменить», как в 1.4.0: она открывает окно
  управления модами (выбрать найденные `.pak`, добавить вручную, удалить, синхронизировать)
  и обновляет список после закрытия; найденные моды ищутся в `Documents/My Games/SnowRunner/base/Mods/.modio/mods`;
* правый клик открывает меню файла: избранное, экспорт и импорт `.epf`, сброс файла;
  меню рендерится порталом в `body`: `filter` на hover строки создаёт containing block
  для `position: fixed` и без портала обрезал бы меню и сдвигал его при уходе курсора;
* пустое состояние предлагает выбрать `initial.pak` и распаковать;
* переход в редактор передаёт `name`, `kind`, `modName`.

Списки файлов кэшируются в `pages/lists/catalog.ts` по загрузчику и категории: переключение
«траки ↔ прицепы» и возврат из редактора не повторяют запрос. Кэш сбрасывается после импорта,
сброса файла и распаковки архива. При возврате из редактора обновляются только избранное
и список изменённых файлов, чтобы метка «изменён» была актуальной.

Картинки берутся из `src/images` (`pages/lists/images.ts`): файлы игры для них не нужны,
без своей картинки показывается `default.webp` категории.
Действия меню лежат в `pages/lists/actions.ts` и открывают документ на время операции —
файл меняют только импорт и сброс.
Распаковка из пустого состояния **не делает бэкап** — в отличие от кнопки на экране игровых данных.

### Редактор (`pages/editor`)

Таблица повторяет 1.4.0: верхнеуровневые группы — аккордеон с серыми заголовками
45px и иконками, открыта только одна группа; поля идут строками «подпись — контрол»,
на ширине от 1430px — в две колонки. Вложенные группы оформлены общей рамкой,
как `Collapse` в 1.4.0, и на каждом уровне открыта только одна группа. Раскрытие
анимируется высотой grid-трека `minmax(0, 0fr)` → `minmax(0, 1fr)`: без такого
минимума padding оставляет 20px и в конце закрытия виден рывок; стрелка — `RightOutlined`;
у раскрытой шапки появляется нижняя рамка, у таблицы и вложенных блоков — скруглённые углы.
Подпись поля, имя связанного файла и текст заголовка группы начинаются с одной вертикали;
у вложенной группы снизу скругляется только последний аккордеон. Имя файла слито
с первой группой, его иконка стоит на линии стрелки. Правый клик по строке поля (включая поле ввода и заголовок
группы) открывает меню сброса.
У прицепа отдельная таблица «Полезное содержимое / Масса / Прочее», у трака — группы ниже.

`TruckTable` собирает группы параметров:

* тексты, управляемость, лебёдка, колёса, подвески, коробки, двигатели, топливо;
* смещение центра масс — в группе «Подвеска», как в 1.4.0;
* разблокировка и цена;
* содержимое аддонов;
* краны, прицепы, «Банан бандита» (карточки в две колонки, как в 1.4.0).

Связанные документы открываются по сокетам трака: двигатели, коробки, подвески, лебёдки,
наборы колёс из `CompatibleWheels`. Отсутствующий файл пропускается.
Группы элементов называются игровыми названиями (перевод `UiName`), а в продвинутом
режиме показывают параметр «Название» с кодом элемента. В продвинутом режиме над связанным
файлом выводится кликабельное имя: оно открывает файл в редакторе системы по умолчанию.
Аддоны открываются по кнопке; повторное открытие возвращает существующий документ.

Пока редактор открыт, Rust-watcher (`watch_documents`) следит за файлами документов
и при изменении извне присылает событие `documents-changed`; интерфейс перечитывает
изменённые модели. Собственное сохранение на короткое время подавляет реакцию.

Шапка редактора: назад, меню (`menu-fold`) со сбросом, экспортом/импортом `.epf`
и подменю «Файлы» (только в продвинутом режиме) и отдельная кнопка сохранения.
Несохранённые правки отмечаются красной звёздочкой `*` возле кнопки сохранения.
При несохранённых правках назад и сброс требуют подтверждения.
Сохранение вызывает `save_all_documents`: команда пишет изменённые документы и сразу
пересобирает исходный архив основной игры или мода. Импорт `.epf` вызывает тот же путь,
поэтому отдельное «Обновить архив» после правки больше не нужно.

«Сбросить» берёт значения из выгрузки 1.4.0 (сжатый `defaults.json.gz` в Rust), а не
перечитывает файл с диска, и не сохраняет документ автоматически: правки остаются
несохранёнными до кнопки сохранения.

### Настройки (`components/settings`)

Модальное окно как в 1.4.0: «Язык программы» и переключатели «Обновлять программу»,
«Редактировать модификации», «Продвинутый режим», «Портативный режим»; закрывается кнопкой «Ok».
Значения сохраняются сразу, смена языка перезагружает окно, переключение режима данных —
с подтверждением и перезапуском. Клиент окна (`settings/client.ts`) подменяется в тестах.

## Компоненты полей

`DocumentField` выбирает контрол по `descriptor.attrType`:

| Тип | Контрол |
|---|---|
| `integer`, `float` | `InputNumber`; `fixed` и integer округляются |
| `boolean` | `Select` да/нет |
| `position` | три `InputNumber` |
| `stringArray` + `options` | `Select` с множественным выбором |
| остальные | `Input` или `Select` при наличии `options` |

Пустой список строк с непустыми `options` трактуется как «все значения» — так же,
как в прежнем интерфейсе. Сброс поля — через контекстное меню (правый клик по всей строке,
включая поле ввода). Подсказка по наведению на подпись — `desc`, на контрол — ограничения
`min`/`max`, значение по умолчанию и цветовые зоны, как в 1.4.0. Жёлтая и красная зоны
меняют цвет рамки поля; логическое значение по умолчанию показывается словами («Да»/«Нет»
или подписью варианта). `Select` подстраивает ширину под выбранное значение и варианты
(не уже 150px), значения выровнены влево. Пустое или недопустимое числовое значение при
потере фокуса возвращает прежнее.

Содержимое аддонов: фильтр по имени и выбор аддона без фильтра «Установленные»
и плашки «Установлен»; четыре поля запасов идут компактной строкой с зазором 8px
между подписью и полем. Select и его список ограничены 300px, длинные названия
обрезаются многоточием. Если в аддоне
нет блока `TruckData`, поля показываются сразу, а блок создаётся при первой правке —
кнопка «Создать TruckData» больше не нужна. В продвинутом режиме есть кнопка открытия
файла аддона во внешнем редакторе.

## Локализация

`src/utilities/localization`:

* `Lang` — `RU`, `EN`, `DE`, `CH`;
* `ru.ts` — эталон структуры, тип `Locale` выводится из него;
* `en.ts`, `de.ts`, `ch.ts` обязаны совпадать по структуре (проверяет TypeScript);
* `T` — выбранный словарь, `setTexts(lang)` вызывается один раз при старте.

Тексты экранов лежат в `T.lists`, `T.editor`, `T.setup`, `T.settings`, `T.updateAlert`, `T.whatsNew`,
`T.welcome`, `T.menu` и `T.dictionaries`. Смена языка в настройках перезагружает окно, поэтому `T` в компонентах достаточно.
Исключение — меню, списки, окно настроек, экран игровых данных, первоначальная настройка
и окно «Что нового»: они читают `LOCALES[config.lang]` из zustand и обновляются сразу.
Подписи полей редактора — `FIELD_TEXTS` в `pages/editor/texts.ts`:
ключ из Rust `модуль.поле` → строка словаря. Значения enum — `OPTION_TEXTS`.

Часть подписей задана русскими строками прямо в `FIELD_TEXTS`; при переводе на другие языки
они останутся русскими. Это известное ограничение (см. [limits.md](limits.md)).

## Состояние и правила

* zustand — только UI-конфигурация; новые межпроцессные данные через него не заводить.
* Игровые данные и документы — в Rust; в компонентах держите только загруженные DTO.
* Локальные черновики полей допустимы, но запись идёт через `DocumentSession`.
* Не обходите `DocumentSession` прямыми вызовами `commands.*` в компонентах.
* Клиенты и загрузчики передавайте пропсами с дефолтом — это точка мока в тестах.

## Стили

SCSS-файл рядом с компонентом (`field.scss`, `lists.scss`, ...); каждый экран/компонент
импортирует свой стиль. Глобальный `src/styles/global.scss` задаёт высоту `html`/`body`/`#main`,
колонку `.app`/`.app-body`, скрытие `.app-screen-hidden` и общий тонкий скроллбар окна.
Используются CSS-переменные antd.

## Тесты
