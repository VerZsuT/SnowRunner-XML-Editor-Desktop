# Roadmap

Статус: **не обязательства**, а направление работ. Приоритеты пересматриваются после релиза.
Последнее обновление: 2026-11-22.

## P0 — завершить релиз 2.0.0

| Задача | Зачем | Готово, когда |
|---|---|---|
| Поднять `site/version-info.json` до 2.0.0 | Сейчас там 1.4.0; автообновление не видит 2.0.0 | Файлы 2.0.0 лежат в GitHub Releases, `version-info.json` обновлён |
| Проверка на чистой Windows 10/11 | WebView2, установщик, портативный режим | Установка/запуск/удаление проходят без ручных правок |
| Проверка обновления с 1.4.0 | Портативные 1.4.0 ждут `.rar`, 2.0.0 — `.zip` | Описан ручной переход; установщик обновляется штатно |
| Пройти ручной чек-лист | Реальная игра и архив | Пункты [testing.md](testing.md) отмечены |
| Переключить GitHub Pages на `/site` | Сайт перенесён из `docs/`, но документация разработчика осталась в `docs/` | Страница загрузки и `version-info.json` доступны по старым URL |

## P1 — надёжность и UX

| Задача | Проблема | Критерий |
|---|---|---|
| Прогресс и отмена длительных операций | Распаковка, обновление и списки не дают обратной связи | События прогресса, кнопка отмены, UI не блокируется |
| Безопасность данных при распаковке | `mainTemp` не очищается, автобэкапа нет | Очистка/учёт файлов, бэкап перед изменением архива |
| Конфликт с внешним изменением | Watcher перечитывает файл и молча отбрасывает несохранённые правки | Диалог «перечитать / оставить своё» вместо автоматического сброса |
| Восстановление датированных бэкапов | UI умеет только `backups/initial.pak` | Выбор бэкапа в UI |
| Синхронизация модов по содержимому | Сравнение только по размеру | Хеш/CRC `.pak` или распакованных файлов |
| Локализация подписей редактора | Часть строк задана по-русски | Все подписи через `FIELD_TEXTS`/локали |
| Тесты на реальном архиве в CI | Фикстура не в git, интеграционные тесты пропускаются | Отдельный job с безопасной копией или генератором |
| Обновление выгрузки значений по умолчанию | `defaults.json.gz` — снимок 1.4.0, сброс не учитывает новые версии игры | Выгрузка из актуальной версии или чтение значений из установленной игры |

## P2 — развитие

| Направление | Комментарий |
|---|---|
| zip64 и data descriptor | zip64 отвергается при чтении, архив с data descriptor нельзя пересобрать; нужны для архивов за текущими лимитами |
| Профили версий игры | Разные структуры `classes`/`_templates` без жёсткой привязки к одной версии |
| Автосохранение/восстановление сессии | Сейчас правки теряются при закрытии приложения |
| Подпись и хеш обновлений | Сейчас доверие только HTTPS и GitHub Releases |
| Пакетная правка нескольких файлов | Сейчас документы открываются по одному |
| Кроссплатформенность | Не планируется: проект ориентирован на Windows и WebView2 |

## Как выбирать следующее

1. Сначала P0: релиз и данные пользователя.
2. Затем то, что уменьшает риск потери данных (P1, безопасность архива).
3. Только потом новые возможности.
4. Любая задача должна иметь проверяемый критерий и тест/чек-лист.

## Не план

* Поддержка Linux/macOS и 32-битной Windows.
* Отказ от Tauri/Rust в пользу Electron.
* Хранение игровых данных в zustand или webview.
* Автоматическая публикация релиза без проверки артефактов.

Связанные ограничения — [limits.md](limits.md); история — [changelog.md](changelog.md).
