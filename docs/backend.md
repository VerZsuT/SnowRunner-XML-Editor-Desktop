# Rust-ядро

Ядро — Cargo-workspace из четырёх пакетов. Tauri-слой тонкий: команды принимают аргументы,
вызывают сценарий и сериализуют DTO. Вся работа с файлами, XML и zip — в библиотеках.

## Состав workspace

| Пакет | Роль | Зависит от |
|---|---|---|
| `sxmle-domain` | XML-дерево, форматирование, кодировки, селекторы; модель игры, поля, дескрипторы | `quick-xml`, `encoding_rs`, `serde`, `specta` |
| `sxmle-storage` | zip-архив игры, атомарная запись файлов | `flate2`, `crc32fast` |
| `sxmle-app` | Сценарии: пути, игра, документы, архив, моды, тексты, EPF, обновления | `domain`, `storage`, `reqwest` |
| `sxmle` | Tauri-команды, `AppState`, ошибки, `specta`, `typegen` | все три + `tauri` |

Правило: `domain` и `storage` не зависят друг от друга и от Tauri. Если логика нужна обоим —
она поднимается в `app` или остаётся в одном слое.

## XML-ядро (`sxmle-domain::xml`)

### Lossless-дерево

`XmlDocument` хранит разметку максимально близко к исходнику:

* порядок и кавычки атрибутов, пробелы внутри тегов;
* комментарии, CDATA, processing instructions, doctype;
* BOM, XML-декларацию и текст после корня;
* несколько корневых элементов: первый — `root`, остальные — `epilog`.
  Файлы игры часто являются фрагментами (`_templates` + `Truck`).

`to_xml()` возвращает документ байт-в-байт (для проверки «не трогали — не изменилось»).
`to_xml_formatted(policy)` — канонический вид; именно он используется при сохранении.

### Форматирование

`FormatPolicy::default()`:

* отступ — 2 пробела;
* перевод строки — CRLF;
* пустые элементы — `<tag />`;
* порядок атрибутов сохраняется, значения экранируются.

Сохранение всегда форматирует документ. Поэтому побайтовая идентичность после правки не гарантируется,
но XML остаётся валидным и игра его принимает.

### Кодировки

`DocumentEncoding` определяется по BOM и объявлению `<?xml version="1.0" encoding="..."?>`.
Поддерживаются UTF-8, UTF-8+BOM, UTF-16LE/BE и кодировки `encoding_rs`.
При сохранении кодировка, BOM и объявление сохраняются. Несовпадение BOM и объявления —
`XmlError::EncodingMismatch`; неизвестная кодировка — `UnsupportedEncoding`.

### Сущности

Известные сущности декодируются при чтении и заново экранируются при записи
(`&amp;`, `&lt;`, `&gt;`, `&quot;`). Одиночный `&` становится `&amp;`.
Неизвестные именованные сущности не раскрываются. DTD не валидируется.

### Селекторы

Стабильный путь узла — строка вида:

```text
/Truck/TruckData
/EngineVariants/Engine[0]
/GearboxVariants/Gearbox[2]/Gear[0]
```

Индекс считается среди одноимённых соседей. Путь разрешается от нескольких корней.
Мутации: `set_attr` (`None` удаляет атрибут), `set_text`, `add_element`, `remove_element`,
`move_element`. Ошибки: `Invalid`, `NotFound`, `Index`.

## Доменная модель игры

### Сущности

`crates/domain/src/game/entities/`:

| Сущность | Назначение |
|---|---|
| `Truck` | корень файла трака/прицепа: `TruckData`, `GameData`, физика, сокеты |
| `TruckData` | управляемость, топливо, колёса, лебёдка, совместимые наборы |
| `TruckGameData` | цена, разблокировка, UI, сокеты аддонов, краны |
| `Engine` | двигатель и его `GameData` |
| `Gearbox` / `Gear` | коробка, передачи, параметры |
| `SuspensionSet` / `Suspension` | набор подвесок и отдельная подвеска |
| `Winch` | лебёдка |
| `Wheels` / `Wheel` / `TruckTire` / `TruckRim` | наборы колёс и отдельные колёса |
| `TruckAddon` | аддон, его `TruckData`, `GameData`, `InstallSocket` |
| `PhysicsModel` / `PhysicsBody` | масса и центр масс, вложенные тела |

Списки читаются через `variant_readers`: элемент либо на верхнем уровне, либо внутри
`<X>Variants`. Это покрывает разные форматы файлов игры.

### Поля и дескрипторы

`Field<T>` — единица обмена с UI:

```rust
Field {
    value: Option<T>,          // из элемента или шаблона
    default_value: Option<T>,  // объявленный дефолт
    descriptor: AttrDescriptor,
}
```

`AttrDescriptor` — единственный источник правды о поле:

| Поле | Смысл |
|---|---|
| `name` | имя XML-атрибута |
| `selector` | путь элемента, который UI возвращает в мутацию |
| `attr_type` | `string`, `integer`, `float`, `boolean`, `stringArray`, `position` |
| `label`, `desc` | ключи локализации `модуль.поле` |
| `limit` | `min`, `max`, `fixed` (округление до целого) |
| `step` | шаг числового поля |
| `areas` | цветовые зоны |
| `options` | допустимые значения enum/множественного выбора |

UI не парсит `selector`: он передаёт его обратно в команду.

### Значения

Правила совпадают с исторической моделью:

* целое — `parseInt`-подобно: префикс цифр, знак, без мусора после;
* float — `parseFloat`-подобно, включая экспоненту;
* boolean — строго строка `true`;
* список — через запятую, элементы обрезаются, пустые отбрасываются;
* позиция — `(x; y; z)`, координаты через `;` или `,`.

При записи: числа как `String(number)`, boolean — `true`/`false`, список — через запятую,
позиция — `(x; y; z)`.

### Шаблоны `_templates`

`Templates` читает `_templates/<name>.xml`, поддерживает `Include`, цепочку `_template`
у элемента и предков, защиту от циклов (глубина 16). Если атрибута нет в элементе,
`AttrReader` берёт значение из шаблона; пустое значение считается отсутствующим.

## Хранилище (`sxmle-storage`)

### Zip

`ZipArchive` читает EOCD и central directory, затем потоково распаковывает записи.
Поддерживаются методы `stored` и `deflate`; проверяются CRC32 и размер.
Не поддерживаются: zip64, data descriptor, шифрование, другие методы.

Обновление (`zip::update`):

1. читает central directory и сохраняет порядок записей;
2. изменённые файлы сжимает тем же методом, что был у записи;
3. неизменённые записи копирует сжатым потоком без пересжатия;
4. новые записи добавляет в конец;
5. пишет новый central directory и EOCD;
6. синхронизирует временный файл и атомарно заменяет исходный.

Метаданные (метод, время DOS, версии, атрибуты, «сырые» имена с обратными слэшами)
сохраняются. Имена не нормализуются.

### Файлы

`fs::write_atomic` пишет во временный `<path>.tmp`, делает `sync_all` и переименовывает.
При ошибке временный файл удаляется, целевой остаётся прежним.

## Сценарии (`sxmle-app`)

| Модуль | Ответственность |
|---|---|
| `paths` | режим данных, каталоги, json-файлы, URL сайта и релизов, смена режима |
| `game` | `GameDirs`, `GameFiles`, приоритет DLC → мод → `classes`, списки траков/прицепов/аддонов |
| `documents` | реестр `Documents`, `docId`, `revision`, `dirty`, сохранение/сброс, EPF |
| `archive` | распаковка по спискам, обновление из каталога, проверка, бэкап, восстановление |
| `actions` | краны, прицепы, «Банан бандита»: правки сокетов и блокировок |
| `epf` | экспорт/импорт `.epf` версии 3.0 |
| `mods` | `mods.json`, распаковка `.pak`, санитайзинг имён, синхронизация |
| `texts` | `strings_<язык>.str` игры и модов, UTF-16LE |
| `lists` | избранное и изменённые файлы, атомарная запись |
| `config` | `config.json`, дефолты, валидация языка |
| `updates` | сравнение версий, `version-info.json`, загрузка установщика/zip |
| `system` | открытие URL, файлов и проводника |

### Реестр документов

`Documents` — `HashMap<docId, Document>`:

* открытие идемпотентно по пути: повторное открытие возвращает существующий документ;
* `docId` — `doc-1`, `doc-2`, ...;
* `revision` растёт при каждой успешной мутации и при сбросе;
* `apply_defaults` применяет выгрузку 1.4.0 ко всем найденным путям за одну мутацию,
  отсутствующие элементы пропускаются;
* `dirty` ставится мутацией и снимается сохранением; `reset_document` перечитывает файл
  с диска, `reset_document_defaults` меняет значения в памяти и оставляет документ изменённым;
* закрытие изменённого документа без `force` — ошибка `Conflict`;
* `open_at` принимает только путь внутри данных игры, DLC или мода.

Шаблоны кэшируются в `TemplateCache`: файл читается один раз, отсутствие тоже кэшируется,
смена каталога шаблонов сбрасывает кэш.

### Сохранение

`save` пишет `to_bytes_formatted(FormatPolicy::default())` в исходный путь документа
атомарной заменой; кодировка и BOM сохраняются. `save_all` сохраняет только `dirty`-документы.
Сам реестр архив не трогает: команды Tauri после записи пересобирают `initial.pak` или `.pak` мода.

## Tauri-слой

`src-tauri/src`:

* `commands/` — по файлу на группу команд; все регистрируются в `commands/mod.rs`;
* `state.rs` — `AppState` с мьютексами и путями;
* `error.rs` — `CommandError` и `ErrorCode`, преобразования из доменных ошибок;
* `defaults.rs` — сжатая выгрузка 1.4.0 (`assets/defaults.json.gz`), её распаковка,
  преобразование селекторов `nth-of-type` в пути модели;
* `lib.rs` — `specta_builder()`, регистрация типов, событий и `invoke_handler`;
* `bin/typegen.rs` — запись `src/api/bindings.ts`.

Контракт описан в [ipc-contract.md](ipc-contract.md).
